Never miss a SECRET,
OG or MYTHIC drop.

A single-file Swift watcher that screenshots your Roblox window, reads the bottom-right event HUD with Apple’s on-device OCR, and fires an @everyone Discord alert just before a rare event lands — then live-edits that same message into a second-by-second countdown.

Download the .swift Setup guide

What it does

Read-only screen capture and OCR. Nothing is injected into Roblox and no memory is read.

🎯⛏️⚡

All three HUD slots

The named rotating event on top, Junkyard in the middle, Blitz at the bottom — each tracked separately.

👑

Nine events, two languages

Roadway, Dragrace, Gold, Diamond, Rainbow, Mythic, Legendary, Secret and OG — matched in English and German, since the HUD mixes both.

⏳

Lead-time pings

Stays quiet until the event is inside alertLeadSeconds, so a 45-minute timer isn’t a 45-minute ping.

⏱️

One message, live

A single message is edited in place every two seconds, so the number on screen is never more than about three seconds stale.

🔔

Role ping per event

Pings one configured role — never @everyone — with a fresh message for each new event, so every cycle notifies.

📐

Position-aware parsing

Rows are matched to a learned screen position, so a row Vision misses can’t shift the other two into the wrong slots.

🗓️

Schedule fallback

If the name can’t be read, a countdown landing on :55 is Roadway and one on :25 is Dragrace.

Setup

macOS 13 Ventura or newer, with Xcode or the Swift toolchain installed.

  1. Create a Discord webhook — channel → Edit Channel → Integrations → Webhooks → New Webhook → Copy URL.
  2. Export it as an environment variable. The script refuses to start without it, so the secret never has to live in the file.
  3. Run it with Roblox already open.
  4. Grant Screen Recording when macOS asks: System Settings → Privacy & Security → Screen & System Audio Recording → enable your terminal, then restart the terminal.
export DISCORD_WEBHOOK_URL="https://discord.com/api/webhooks/..."
swift watcher/RobloxEventWatcher.swift

Prefer a standalone binary? Compile it once and run that instead:

swiftc -O watcher/RobloxEventWatcher.swift -o roblox-watcher
./roblox-watcher

First run on a new resolution? Start it with debug output and check that all three rows land inside the crop:

WATCHER_DEBUG=1 WATCHER_TEST=1 swift watcher/RobloxEventWatcher.swift
open ~/Desktop/roblox-debug.png

WATCHER_TEST=1 posts one message to the webhook at startup, so you know the Discord side works before waiting on an event.

Rotate your webhook. The webhook URL that was hard-coded in the earlier version of this script is a password for your channel — anyone holding it can post there. Delete that webhook in Discord, create a new one, and pass it through DISCORD_WEBHOOK_URL. Never commit it.

How it works

One loop, four steps, entirely on-device.

  1. Find the window. SCShareableContent prefers com.roblox.RobloxPlayer above 1000×700, and otherwise falls back to the largest Roblox window.
  2. Capture & crop. SCScreenshotManager grabs the window, then the bottom-right HUD is cropped (the last 16% in each direction) and upscaled 6× with high-quality interpolation so small text survives OCR.
  3. Recognise. VNRecognizeTextRequest runs at .accurate with language correction off — it must not "helpfully" turn RAINBOW into a dictionary word. Each line keeps its vertical position and its top three candidate readings.
  4. Assign and decide. Lines are sorted top-to-bottom and the three timers map onto the rotating / Junkyard / Blitz slots. Once all three have been seen, their vertical positions are remembered, so a later reading that misses one still assigns the rest correctly. Each slot runs its own countdown independently.

OCR syncs a clock, it doesn’t drive the countdown

A screenshot every second to show a ticking number would be wasteful and fragile. Instead each reading is converted into a deadline, and the remaining time comes from the system clock after that. OCR only re-syncs, every ten seconds, and a disagreement of one or two seconds is treated as HUD rounding and ignored so the display never jitters. The useful side effect: a frame Vision fails to read no longer stalls the countdown — it just keeps ticking until the next successful sync.

One message per event

Each event cycle gets its own Discord message, because only a new message notifies — an edit never does. A new event every five minutes therefore means a ping every five minutes. Within a cycle that one message is edited in place, at most every two seconds, which keeps it under the webhook rate limit (with retry_after honoured on HTTP 429). If the same title restarts within duplicateGuardSeconds it reuses the existing message instead of posting a duplicate — that catches an OCR dropout mid-countdown.

Which row is which

The two timer formats aren’t interchangeable: the top slot always counts as 2:21, the lower two always as 7m 21s. So the format identifies the row the same way the icon beside it does — except it’s already in the text, with no image classification and nothing to misread. Exactly one M:SS line means that line is the event, wherever it sits and however many rows were read. Junkyard and Blitz then fall out by vertical order, with their learned positions covering the case where only one of them is legible.

Reading two timer formats

The top slot counts in M:SS while the lower two use 15m 14s, so the parser tries unit-suffixed durations first (1h 05m 14s, 45s) and clock form second (0:14, 1:02:03). Common OCR slips — O for 0, I/l for 1 — are repaired before matching.

Reading the event name

The orange label is the smallest text on screen and the hardest to read, so it gets three passes. The crop is upscaled 6× and minimumTextHeight is lowered so Vision doesn’t discard it; every one of Vision’s top three candidate readings is fuzzy-matched, not just the best; and if a timer was found but no name, the frame is re-run with language correction and the nine event names supplied as customWords. That second pass is restricted to the top row, so Junkyard and Blitz can’t produce a false match.

Fuzzy matching, carefully

The game runs in German and translates some names but not others — Mythisch for Mythic, yet Rainbow unchanged. Every event therefore maps a canonical name to all the spellings that can appear, matched longest-first so GOLDEN wins over GOLD. Levenshtein tolerance scales with length: 2 edits for long names, 1 for mid-length, and exact match only at three characters or fewer — otherwise OG would match almost any two-letter scrap of text.

Rotation

The top slot runs Roadway at :55 and Dragrace at :25 — each five minutes before the hour and half hour — with rarity events on the remaining five-minute marks. Only those two fixed points are predictable from the clock, so that inference is used solely as a fallback when OCR can’t read the label.

Run with WATCHER_DEBUG=1 to print every OCR line and dump the cropped region to ~/Desktop/roblox-debug.png — that’s how you retune the crop for your own resolution.
